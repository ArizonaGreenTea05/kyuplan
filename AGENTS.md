# AGENTS.md

kyuplan: karate-club exam planner on Spond data. .NET 10 (SDK pinned in `global.json`), C# latest, nullable on.
Read this instead of exploring. Open `README.md` only for the section you need (`grep -n '^#' README.md`).

## Layout (`src/`)
- `Contracts`: wire DTOs and shared rules (`*Rules.cs`). Change here first when the API shape changes.
- `Api`: ASP.NET minimal API. `Endpoints/` routes, `Persistence/` services + EF (SQLite), `Accounts/` users, `Spond/` Spond access, `Statistics/` engine, `Domain/`.
- `Client.Shared`: typed API client, **all view models**, **all UI texts** (`Resources/Strings.resx` + `Strings.de.resx`). No UI-framework code.
- `Client.Blazor` (WASM) and `Client.Wpf` (Windows only): markup only; bind to the shared view models.
- `website/`: Docusaurus, one site per audience (user/admin/deployment, developer) built from `docs/*.md` (`scripts/audiences.mjs`: which file is a page of which site). The API serves the first three under `/docs/<audience>/`
  with a permission check per audience (`Contracts/Documentation.cs`, `Endpoints/DocumentationEndpoints.cs`); clients show `ShellViewModel.HelpLinks`. A new doc file = an entry in `audiences.mjs`. Node is not needed for `dotnet test`; the Dockerfile's `docs` stage and the release's `docs` job build it.
- `tests/Kyuplan.Tests`: single xUnit project.

Logic goes in `Client.Shared` or `Api`, never duplicated in the UIs.

## Commands
- Build/test (Linux-safe, skips WPF): `dotnet test tests/Kyuplan.Tests`. Narrow with `--filter "FullyQualifiedName~Name"` (a class name; several test classes share a file, e.g. `ResourceFileTests` is in `LocalizationTests.cs`).
  On Linux a clean run still shows 7 failing `DpapiLoginStoreTests` (DPAPI is Windows-only; CI runs on Windows) and 3 skipped `PostgresApiTests` (no `KYUPLAN_TEST_POSTGRES`): expected, not your change.
- `Client.Wpf` and the full `.sln` build only on Windows; on Linux skip them.
- A running Api locks its DLLs (MSB3021): stop it, or build/test with `--artifacts-path artifacts/<name>` (inside the repo, `artifacts/` is git-ignored). Not outside it: `AccessibilityMarkupTests` walks up from the test binaries to `global.json`, so a path like `/tmp/x` fails those 10 tests.
- Run API in demo mode (no Spond credentials): `dotnet run --project src/Kyuplan.Api --launch-profile http -- --Spond:UseDemoData=true` (port 5100, docs at `/scalar`). The launch profile alone does NOT enable demo data.
- Every API call needs HTTP Basic login; a new API has no user: the Blazor client then shows a setup screen (settings + first admin, `Endpoints/SettingsEndpoints.cs`), or set `Accounts:InitialAdminPassword`. Settings live in `data/settings.json` (read on top of appsettings, saving restarts the app inside `Program.cs`'s loop); tests set `Setup:SettingsFile` to a missing file. Authorization is permission/role based (see `Accounts/PermissionAuthorization.cs`), there is no admin flag.
- Browser smoke tests of the Blazor client (Playwright, demo data, screenshots of every page): `cd tests/ui && npm install && npx playwright test`; details in `docs/developer-guide.md#browser-smoke-tests`. A new Blazor page = an entry in `tests/ui/smoke.spec.ts`. WPF page screenshots (Windows, needs a running demo API): `tests/Kyuplan.WpfShots`, see `docs/developer-guide.md#wpf-screenshots`.
- Before `dotnet ef`: `dotnet tool restore` (tool pinned in `.config/dotnet-tools.json`) and rebuild the Api project.

## Rules that bite
- **Texts**: add each new key to BOTH `Strings.resx` and `Strings.de.resx` with identical `{0}` placeholders (`ResourceFileTests` enforces it). The `Strings` class is generated at build time. Razor `@Strings.X`, XAML `{loc:Loc X}`. No hard-coded UI strings.
- **DB schema**: edit `Persistence/Entities.cs` / `PlannerDbContext.cs`, then add a migration (applied on API start):
  `dotnet ef migrations add <Name> --context PlannerDbContext --project src/Kyuplan.Api --output-dir Persistence/Migrations`
  Accounts DB: `--context AccountsDbContext --output-dir Accounts/Migrations`. Never hand-edit existing migrations.
  **Every schema change needs the PostgreSQL twin** (`PostgresMigrationTests` fails otherwise): same command with `--context PlannerPostgresDbContext --output-dir Persistence/PostgresMigrations` (accounts: `AccountsPostgresDbContext`, `Accounts/PostgresMigrations`), build first, and pass the provider to the app host: `-- --Database:Provider=PostgreSql --Database:ConnectionString="Host=x;Database=x" --Accounts:ConnectionString="Host=x;Database=x"` (no server is contacted). Provider differences of the model live in `Infrastructure/PostgresModel.cs` and `PlannerDbContext` (`IsColor`); catch unique/foreign-key violations with `DbUpdateException.IsUniqueViolation()/IsForeignKeyViolation()`, never with `SqliteException`.
- **Themes**: themes the clients draw themselves are `ThemeIds`; everything else is a **theme pack** (JSON of 12 colours, `Contracts/ThemePacks.cs`, built-ins in `BuiltInThemePacks`, uploads as files in `Themes:Directory` via `ThemePackStore`). New palettes/accessibility themes = a pack, not client code. Both clients derive everything from the 12 colours (`js/theme.js`, WPF `ThemePackColors`); a built-in pack must pass `ThemePackRules.Check` (`ThemePackRulesTests`).
- **Database/deployment**: `Database:Provider` (`Sqlite` default | `PostgreSql`) applies to both databases; contexts are chosen in `Infrastructure/DatabaseRegistration.cs`. One image for every Docker host (`src/Kyuplan.Api/Dockerfile`, amd64+arm64, `GET /healthz`), Compose files in `deploy/` (generic, PostgreSQL, TrueNAS); all options and extra steps are in `docs/deployment.md`: update it with any change there.
- **Releases**: one tag `v<version>` releases everything (`.github/workflows/release.yml`, see `docs/deployment.md`): the desktop installers (one per platform, `Kyuplan-<platform>-<version>.<ext>`, ids in `ClientPlatform`) are built first and baked into the one Docker image (`downloads/`, Dockerfile build context `installer`); the API offers them (`GET /api/client/<platform>`, `ServerInfoDto.ClientVersions`), the Blazor sidebar shows a download button for the visitor's system, and each desktop client updates itself via `ClientUpdateViewModel` + its `IClientUpdater`. A client for a new OS plugs in there (see `docs/deployment.md`), nothing platform-specific in the API/web client.
- **Data sources** (`Spond/IDataSource.cs` + `Sources/`): every source implements `IDataSource` (Spond, demo, `CustomScriptDataSource` = admin JavaScript run in Jint, `ManualDataSource` = rows of the `Manual*` tables); `DataSource:Kind` (+ `Spond:UseDemoData`, which wins) picks one at start in `Program.cs`, the settings page changes it and restarts. Manual data: `ManualDataService` + `ManualDataEndpoints` (`/api/manual`, permission `manualdata.edit`, syncs members/exams after every write), `ManualDataViewModel` (Client.Shared), `ManualData.razor`, `ManualDataView.xaml`. Script contract and limits: `docs/admin-guide.md#custom-data-source`. A new schema/table needs the usual two migrations.
- **Calendar feeds** (`Persistence/CalendarFeedService.cs` + `IcsWriter.cs`, `Endpoints/CalendarFeedEndpoints.cs`, `Contracts/CalendarFeedDtos.cs`): admin-defined ICS calendars, sources stored as JSON in `CalendarFeeds.SourcesJson`; `GET /calendar-feeds/{token}.ics` is anonymous on purpose (the token is the key, outside `/api` so the API key middleware does not apply); permission `calendar.feeds`; docs in `docs/admin-guide.md#calendar-feeds`. Page: `CalendarFeedsViewModel` + `CalendarFeedEditorViewModel` (Client.Shared), `CalendarFeeds.razor`, `CalendarFeedsView.xaml` (Administration).
- **Backups** (`Api/Backup/`, `Endpoints/BackupEndpoints.cs`): a `.kyubackup` zip holds both databases as JSON rows per table (`DatabaseCopier` works on the EF model, so SQLite and PostgreSQL are interchangeable; a table with a shadow property makes `DatabaseCopier.Tables` throw, `BackupApiTests` catches it). Mirror databases (`BackupTargetStore`, JSON file, not in the DB) are refreshed by `BackupWorker`; a restore restarts the app. A new table needs nothing extra; a new schema needs the usual migrations. Page: `BackupViewModel` + `Backup.razor` + `BackupView.xaml`; options in `docs/admin-guide.md#backups`.
- Package versions live in `Directory.Packages.props` (central); csproj files carry no versions.
- **Exam prices/payments**: `ExamPrices` (general fee = row without belt, surcharge per belt) + `ExamPayments` (paid + due snapshot per exam/member), `ExamPaymentService`, `PaymentEndpoints`, `ExamPricesViewModel` (page) and `PaymentRow` in `ExamDetailViewModel`; rules in `docs/exam-planning.md#prices-and-payments`. Amounts are `decimal`, validated by `PaymentRules`.
- Domain rules are documented in `docs/` (`attendance-statistics.md`, `exam-planning.md`, `comments-and-tags.md`). Read the matching file before changing that logic, and update it with the code.
- Tests use in-memory SQLite (`InMemoryDatabase.cs`). Add tests next to the closest existing `*Tests.cs`. Test hosts must set `Sync:Enabled=false` and `DefaultData:Enabled=false`, and must not depend on shipped `appsettings.json` values (that once broke every CI workflow).
- **Accessibility**: every focusable control has an accessible name (WPF `AutomationProperties.Name` with the same `{loc:Loc}` key as its label, Blazor label/`aria-label`), nothing leaves the tab order, no `role="menu"`; `AccessibilityMarkupTests` enforces it, keyboard glue is `Client.Blazor/wwwroot/js/a11y.js`.
- Both UIs must keep working: a change to a view model or contract may need Blazor and WPF edits.

## Wiring you would otherwise grep for
- **Auth**: the fallback policy demands a login; an endpoint adds `.RequirePermission(anyOf…)`. Public on purpose: `/healthz`, `/api/branding*`, `GET /api/themes`, `/api/setup`, the calendar-feed `.ics`, `/metrics` (own token), Scalar in Development. `Permission.Reads*` are the any-of lists for reads that several pages share. Guards: `AccountApiTests.Every_api_endpoint_needs_a_login` (allow-list of public routes) and the table `PermissionApiTests.Endpoints()` (method, url, body, permissions: one row per new endpoint, and every catalogue permission must appear in it). A new permission reaches only the administrator role by itself; `DefaultRoles` only seeds new databases.
- **Errors**: services throw `*NotFoundException` (404), `AlreadyExists`/`BeltInUse`/`LastAdmin`/… (409), `InvalidInputException` (400), `ForbiddenException` (403), `SpondUnavailableException` (503), mapped in `Infrastructure/ApiExceptionHandler.cs` (a new exception type must be added there). DTO checks live in `Contracts/*Rules.cs`; endpoints answer `Results.ValidationProblem`.
- **Audit log**: change endpoints of exams, payments, belts, members, users, roles end in `.Audited(AuditAreas.X, AuditActions.Create|Update|Delete)` (written after a 2xx; the body is stored with `*password*` keys removed). A new area = `AuditAreas.All` + an `AuditArea_<area>` text in both resx.
- **Time**: days and "today" go through `ClubClock` (`Statistics:TimeZone`, DST-safe) and the injected `TimeProvider`, never `DateTime.Now`; tests pin it (`FakeTimeProvider`; `PinnedNow` = 13 Oct 2026).
- **View models** are singletons. `ViewModelBase.LoadAsync` cancels superseded loads and turns `PlannerApiException` into `ErrorMessage`; `PageViewModel` adds `ViewPermission` (null = every user), `ReloadAsync`, `ReloadsWithContext`/`ReloadsOnActivation`. A new page: register it in `AddPlannerClient`; `IPlannerApi` + `PlannerApiClient` + `FakePlannerApi` members; the WPF `MainViewModel` lists (main/admin/account); the Blazor nav in `Layout/MainLayout.razor`.
- **Blazor**: a page is `@inherits ViewModelComponent<TVm>` with `<BrandedTitle>`, `<ErrorBanner>` and its body in `<PageGate Page="Vm">`; JS glue in `wwwroot/js/` (`a11y`, `lang`, `theme`, `brand`, ...). The Api project references the Blazor project and serves it, so building the Api builds the web client; `dotnet run` serves its static files only in Development (why the smoke tests run in Development).
- **WPF designs**: every page is the same XAML in all designs (`Themes/Design.*.xaml` + `Controls.Classic` + `Colors.*`). A `{DynamicResource X}` that one design lacks only shows when a user picks it; `DesignContractTests` (reads the XAML as text, runs on Linux) lists the names each design must define.
- **Config**: the README configuration table gives the code defaults (`Configuration/Options.cs`); the shipped `appsettings.json` overrides some (attendance 60 %, sync every hour, Spond cache 30 min, `IgnoreAdministrators`), hence the rule that tests must not read it.
- **Spond** is read-only. Spond.API swallows HTTP errors as empty lists and never refreshes its token; `SpondApiDataSource` logs in again and treats "no groups" as a failed login. **Demo data** (`DemoDataSource`): groups `demo-dojo` (30 members; subgroups `sg-kids`, `sg-youth`, `sg-adults`) and `demo-team` (8); events are generated around today (exams every March and September); the Exams list stays empty until someone makes an event an exam.
- **Domain in one breath** (rules in `docs/`): attended = accepted RSVP; engagement = 60 % attendance + 25 % recent form + 15 % answered; a member is judged for the next belt on the exam day (attendance, average stars ≥ `ExamMinAverageStars`, age, waiting time); an attended event nobody evaluated counts 2.5 stars; an exam costs general fee + stamp fee + belt price (no belt price for "own belt"); comments use a small markup and are never rendered as HTML.

Node 22 is there.
- The full `dotnet test` (1756 tests) takes 5-7 minutes with the build: run it once, in the background, at the end.
- Demo API from `src/Kyuplan.Api` with `Accounts__InitialAdminPassword=<12+ chars>` (user `admin`); point `Database__ConnectionString`, `Accounts__ConnectionString` and `Setup__SettingsFile` at a temp folder to keep `src/Kyuplan.Api/data` clean. Never `pkill -f Kyuplan.Api.dll` (the pattern also matches your own shell): kill by PID.
- Browser smoke tests work (48 pass, ~2 min). Playwright is pinned to 1.55 (Chromium revision 1187) but the sandbox has 1194 in `/opt/pw-browsers`: make a folder with symlinks `chromium-1187` -> `chromium-1194`, `chromium_headless_shell-1187` -> `chromium_headless_shell-1194`, `ffmpeg-1011`, and run with `PLAYWRIGHT_BROWSERS_PATH` pointing at it (no download). `npm install` there writes an untracked `tests/ui/package-lock.json`: do not commit it.
- `gh` is installed but its `GH_TOKEN` can be invalid here (`gh auth status`), so the `issue-reviewer` agent's `gh issue view` can fail: read issues and PRs with the GitHub MCP tools.

## Tests and coverage
- **Every change ships with tests**: new code, bug fixes (a test that fails without the fix) and changed behaviour. No task is done without them, even if not asked.
- Aim for the highest realistic coverage: cover every branch, validation rule, error path and edge case (empty, null, boundaries, duplicates, permission denied/401/403/404, invalid input) of the code you touch, not only the happy path. Prefer view-model and API tests over UI tests.
- **Hunt for edge cases beyond line coverage**: before finishing, list how the change could break (whitespace/very long/unicode strings, case differences, zero/negative/max values, `decimal` rounding, dates around midnight, time zones, DST and year boundaries, empty and single-item collections, duplicates, concurrent or repeated calls, missing or deleted related rows, German vs English culture) and add a test for each that is plausible. Use `[Theory]` for value ranges. Coverage numbers do not replace this.
- Only leave code uncovered when testing it is not realistically possible (WPF/Blazor markup, OS-specific or process-restart code); say so in the final report.
- Check with `dotnet test tests/Kyuplan.Tests --collect:"XPlat Code Coverage"` when touching larger areas, and add tests for uncovered lines of the changed files.
- **Test kit**: API tests = `WebApplicationFactory<Program>` + two `InMemoryDatabase`s + `TestAccounts.Configure` (user `admin`, password `test-admin-password`) + `CreateSignedInClient()`; sync tests = `SyncTestClub` + `FakeSpondDataSource` (can be made unreachable); view-model tests = `FakePlannerApi` (every new `IPlannerApi` member needs an implementation there); `[PostgresFact]` for what needs a real server. WPF files compiled into the test project: `DpapiLoginStore`, `AccentShades`, `SvgSafety`, `MainViewModel`.
- **A German text identical to the English one** (names, formats, loan words) must be added to the list in `ResourceFileTests.Every_text_is_actually_translated_apart_from_a_few_that_read_the_same`, or that test fails.
- **Known flake**: `SyncStatusTrackerTests.The_metrics_count_the_runs_by_outcome_and_tell_when_it_last_worked` can fail in a full parallel run (every `SyncStatusTracker` makes its own `Meter("Kyuplan")`, so the listener also hears the syncs of tests running at the same time: 2 successes instead of 1) and passes alone. Rerun it by itself before suspecting your change.

## Token savers
- Don't read `Migrations/*`, `*.Designer.cs`, `wwwroot/`, `assets/`, `installer/`, `deploy/`, `bin/`, `obj/`, `logs/`, `.github/` (read `.github/` and `deploy/` only when changing releases). Irrelevant to almost every task.
- Use `grep`/Glob to locate a symbol, then read only that range (offset/limit). Don't read whole files or the whole README.
- Don't re-run the full test suite after each edit; run the filtered test, then the full suite once at the end.
- Keep final reports to a few lines: what changed, where, test result.

## Git
The repo uses LF line endings; check with `git ls-files --eol` and keep edited files LF.
In a shallow clone (cloud agents), before pushing `git fetch origin <default-branch>` and rebase, so the push stays a thin pack.
Default branch `main`; merged commits read `feat: … (#NN)` / `fix: …`. CI (`.github/workflows/ci.yml`): `build-test` (Windows: `dotnet build -c Release`, then the tests), `postgres` (`PostgresApiTests` on postgres:16), `docs`, `ui-smoke`, `wpf-screenshots`, `image` (Docker build, no push). `pr-review.yml` lets Claude review every non-draft PR of this repo against the rules above.
